**For the Galaxy S9 SM-G9600 only** (Snapdragon 845, `starqltechn`). Installing it **erases `userdata`** (all Android data). One phone, one tester: read the [front page](https://github.com/inaciopestana/ubuntu-2404-starqltechn#installation-at-a-glance) and [`docs/installing.md`](https://github.com/inaciopestana/ubuntu-2404-starqltechn/blob/main/docs/installing.md) first, and **back up first**.

The idea of the project is the Galaxy S9 as a **portable PC**: Ubuntu 24.04 with XFCE, meant to be used with a **mouse and a keyboard** (USB-C hub or Bluetooth). Touch works, but it was not designed around it, and **there is no on-screen (virtual) keyboard** in this system.

## Install

Needs: Samsung stock Android 10 (PDA `G9600ZHU9FVF2`) on the phone, bootloader unlocked, and the phone connected to the internet at least once so the *OEM unlocking* item shows in Developer options (otherwise Odin says `FAIL! (Auth)`). Not there? [Returning to stock Android](https://github.com/inaciopestana/ubuntu-2404-starqltechn/blob/main/docs/returning-to-android.md).

**1. TWRP.** Phone off, then Download Mode: hold Volume Down + Bixby, plug the cable, press Volume Up. On Linux, with the files in the current folder:

```
odin4 -a twrp-3.7.0_9-0-starqltechn-settings-cache.tar
```

On Windows use Odin with the file in the AP slot. When it finishes, boot straight into TWRP: Volume Down + Power for about 10 s, and right away Volume Up + Bixby + Power.

**2. Disabler.** In TWRP, with the cable connected:

```
adb shell twrp sideload
```
```
adb sideload S9_G9600_disabler-and-encryption-removal.zip
```

Do not boot Android afterwards.

**3. Ubuntu.** Again in TWRP (about 9 minutes, no microSD card needed):

```
adb shell twrp sideload
```
```
adb sideload s9-clean-20261103-121804.zip
```

When the log says `DONE`, reboot.

**4. First boot.** A window asks for your **user name, password and host name**, then the phone restarts. Connect to Wi-Fi from the network icon in the tray: Chrome is downloaded from Google and installed within about 30 seconds of getting a network (it is not inside the ZIP, because it is Google's proprietary package).

If `adb sideload` times out, connect the phone through a USB 2.0 hub. If it ends at once (`Total xfer: 0.00x`), read the log: [`docs/installing.md`](https://github.com/inaciopestana/ubuntu-2404-starqltechn/blob/main/docs/installing.md#installing-the-ubuntu-zip-over-the-cable). A microSD card also works (TWRP > Install; never from the internal storage).

Check the files first with `sha256sum -c *.sha256`.

## What the Ubuntu ZIP does

It writes the Ubuntu root image into `userdata` (1 MiB from its start) and then the boot image into `boot`, reading both back and comparing SHA-256 values. It never touches `system`, `vendor`, the modem or `efs`. It refuses to run from the phone's internal storage.

Contents: Linux 4.9.186 (FakeShell `ubports` tree + [`kernel/patches`](https://github.com/inaciopestana/ubuntu-2404-starqltechn/tree/main/kernel/patches)); Ubuntu 24.04 arm64 with XFCE, patched Mir/MirAL, Xwayland, Freedreno/KGSL Mesa, the Halium 10 container, telephony and audio. Not included: Samsung/Qualcomm firmware (the Adreno 630 firmware is copied at the first boot from your phone's own `vendor` partition), Google Chrome (downloaded at the first boot) and any personal data. Licences and source locations: [`THIRD_PARTY.md`](https://github.com/inaciopestana/ubuntu-2404-starqltechn/blob/main/THIRD_PARTY.md). The licences of the two disabler originals are not verified (see that README).

## What is tested

The author went from this port back to stock Android and installed it again **twice**. The first time he fixed the problems of each step (they are in the docs); the second time he used only the files of this release (this very `s9-clean-20261103-121804.zip` included) and it went through with no problem. Earlier builds of the ZIP had two bugs, fixed in this one: the GPU device group was missing (OpenGL failed for the user), and NetworkManager made a useless "Wired connection 1" on `p2p0`. This build also has the new DeX fan tray icon (fan with the level word) and retries the Chrome download every 30 seconds instead of every 5 minutes.

Not tested: a run by anyone but the author, the microSD route and `flash-from-pc.sh` on a real phone, Odin on Windows, flashing with a graphical Odin front end. Hardware H.264 decoding shows repeated frames.

Image builder: commit [`ff43fc7`](https://github.com/inaciopestana/ubuntu-2404-starqltechn/commit/ff43fc7).
